# Murmur post-processing prompts

Context design: `docs/ml/CONTEXT_V2.md` (binding: the screen context is what OCR sees) and, for history,
`docs/ml/CONTEXT_AND_PROMPT.md`. Measurements and the recommended prompt: `docs/ml/PROMPT_EVAL.md`.
Eval tooling: `prompts/eval/README.md`. Everything is stdlib Python 3.11+.

## Ship list (what the app uses)

| Model state | Profile | System prompt | Few-shot turns | Context |
|---|---|---|---|---|
| stock model (no fine-tune) | `profiles/default.v4.json` | `system/default.v4.md` | `shots/default.v4.jsonl` (15) | ctx v2, `render.CTX2_DEFAULT` |
| stock, short prefix | `profiles/default.v4s.json` | `system/default.v4.md` | `shots/default.v4s.jsonl` (8) | same |
| Murmur fine-tune | — (`render.chat`) | `system/finetuned.v1.md` (training uses it today; `finetuned.v2.md` = OCR wording, adopt with the next fine-tune) | none | ctx v1 or v2 as in the training data |

The recommended default per model and the numbers behind it are in `docs/ml/PROMPT_EVAL.md`.

## Request assembly (byte-exact, cache-friendly)

```
[chat template header] SYSTEM = system prompt (+ preferences block)
[few-shot user/assistant turns of the profile]                      <- identical for every request: cache its state
USER = "Style: <tone>\n" + "<context>\n…\n</context>\n" + "<transcript>\n<ASR text>\n</transcript>"
[assistant opener, thinking disabled] + profile answer_prefix (empty in all shipped profiles)
```

ctx v2 `<context>` block (shipped options, see `render.CTX2_DEFAULT` and `examples/ctxv2_chat_ru.context.txt`):

```
App: Telegram — message field
Field hint: «Сообщение»                                (if the node has a hint)
Dictation language: Russian
Text already in the field before the cursor: «…»      (last 300 chars, if any)
Screen text (OCR, nearest to the field first):        (if any line survives the filters)
<one OCR block per line: wrapped lines merged, clock/status lines, low-confidence, 1-char and repeated lines
 and the field's own text dropped; ranked by vertical distance to the field; at most 1,400 characters>
</context>
```

* Nothing request-specific goes into the system prompt or the shots, so the prefix KV state can be computed once per
  model load and restored (`llama-server` slot save/restore; on the phone: llama.cpp state file, NPU runtime U).
* Screen text goes through `clean()`: control/bidi characters removed, `<` `>` → `‹` `›` (screen text can never
  open or close a tag).
* Thinking disabled: Qwen3.5/Qwen3 → `<think>\n\n</think>\n\n`; LFM3 → `<think></think>`; LFM2.5 has no thinking.
* Decoding: greedy (temperature 0, top-k 1), no repetition/presence penalty, `n_predict = min(1024, 2·transcript_tokens + 64)`,
  stop at `<|im_end|>`.
* App flow around the LLM: `guard.precheck(transcript)` first (noise/filler-only/known ASR hallucinations → insert
  nothing, no LLM call); then the LLM; then `guard.guard(transcript, output, ctx)` (fallback to the raw transcript).

## Rules for editing the prompt

1. Bump the version (`default.v5`) instead of editing a released file; the app stores which version produced each history item.
2. `make -C prompts sets goldens test`, then run the dev sweep (`make -C prompts sweep SET=dev.v2 PROFILES=…`) and compare
   with `make -C prompts report SET=dev.v2`. Look at the held-out test set only for the final candidate.
3. Users edit only the default instructions (stock models) and "My preferences" (all models). "Reset to default"
   restores the shipped profile's system prompt.
