# Architecture decision log

Short ADRs, newest last. Each: decision, the conflict it resolves (which documents disagreed), evidence with its
status. Spike reports (`docs/research/verify/*.md`) override phase-1 research where they disagree. "Arch check" =
a command the architect ran on 2026-11-18/19 on this server (output quoted). Owner decisions D1-D12 come first
(verbatim); the review of version 1 and how each finding was handled is at the end ("Review responses").

Identifier namespaces: **D1-D12** = owner/orchestrator decisions (this table only); **DC1-DC10** = steps of
`docs/DEVICE_CHECKLIST.md`; TOOLCHAIN.md and the spike reports use their own local "D" numbers, always cited with the
document name (e.g. "llm spike D5", "TOOLCHAIN D1").

## Owner decisions (binding; text as given by the orchestrator, 2026-11-18)

| # | Decision |
|---|---|
| D1 | minSdk 34, compileSdk/targetSdk as in the verified toolchain, unless the platform spike shows a hard blocker. |
| D2 | NPU-first, honest labelling: the catalog declares for each model which compute units it can run on (NPU / GPU / CPU) and with which artifact; the app defaults to the best available one, shows the unit actually used, lets the user pin one, and the Benchmark button measures the available units on the user's phone. A model the owner asked for that has no NPU path today still appears in the hub, labelled, with "NPU port" recorded as a follow-up work item. |
| D3 | The model hub is catalog-driven: one JSON catalog (bundled, later refreshable) describes ASR, LLM, OCR and VAD models (HF repo, pinned revision, files with sha256 and sizes, params, languages, licence, runtime key, compute units, memory estimate, streaming capability, prompt profile for LLMs). No model-specific code in the UI. Users can also add a custom Hugging Face model for a supported runtime (GGUF for the LLM; a supported sherpa/ONNX layout for ASR) — "the user can configure any model". |
| D4 | Transcription happens during dictation: native streaming for streaming models, VAD-segmented incremental decoding for batch models, hidden behind one session interface (see asr-models.md and the ASR spike's measurements). LLM runs once at the end over the full transcript + context. |
| D5 | Models never live in the UI process and never stay in RAM when idle: inference runs in separate process(es) that load on bubble press (ASR first, LLM in parallel), unload after an idle timeout, and exit. Choose one or two inference processes from the spikes' evidence about QNN/QAIRT stack coupling. |
| D6 | Release ABI arm64-v8a. Debug builds also ship x86_64 with CPU engines so the complete pipeline (bubble -> record -> ASR -> LLM -> insert -> history) runs on the emulator; in addition every engine contract has a deterministic fake for unit and UI tests. |
| D7 | UI is Jetpack Compose and implements docs/design exactly (tokens.json -> theme; adaptive cover/inner layouts). No visual redesign by engineers. |
| D8 | prompts/ is the single source of truth for the post-processing prompt; it is packaged into the APK at build time, and the Kotlin renderer must reproduce prompts/render.py byte-for-byte (golden tests from prompts/examples). Users can edit the prompt in Settings; the default stays restorable. |
| D9 | Privacy: network is used only for model downloads from Hugging Face. No analytics. Screen context is never persisted. History (text + compressed audio) auto-deletes after the retention period (default 7 days, configurable). |
| D10 | Package app.murmur; product name "Murmur" is a working name: keep it in one place. |
| D11 | Screen context = what OCR sees (owner decision; docs/ml/CONTEXT_V2.md is binding and overrides CONTEXT_AND_PROMPT.md sections 1-4): screenshot through the accessibility service about 0.6 s after dictation starts -> on-device OCR (PP-OCRv6 tiny detector + cyrillic PP-OCRv5 mobile recogniser; runtime and compute unit from the ASR/OCR spike; the OCR models are hub catalog items like every other model) -> post-processing ported from the Python reference in ml/ocr/ with a parity test over ml/ocr/golden/ that runs on the host or the x86_64 emulator -> ctx v2 -> the Kotlin renderer (byte-identical with prompts/render.py). The accessibility node tree supplies only the current app, the focused field (kind, hint, text before the cursor, password flag) and the insertion; no screen text is taken from the tree. OCR exclusion rectangles: status bar, IME window, Murmur's own overlay. The screenshot and the OCR text live in memory only. |
| D12 | The phone comes last (owner: "do 100% you can do without it and I will give you access when you test all other parts of the system"). Every work package's acceptance criteria must be checkable on this server: unit tests, the x86_64 emulator with CPU engines and real small models where feasible, deterministic fakes otherwise, including an end-to-end emulator test of the whole dictation flow. No work package may depend on the phone. Everything that only the phone can prove (NPU paths, real latency and memory, One UI behaviour, real-screenshot OCR quality on both displays, fold/unfold) goes into ONE document, docs/DEVICE_CHECKLIST.md: ordered steps, the ready-to-run tools/device/* scripts, expected output, and what decision each result feeds, so that the device session is a single pass. |
